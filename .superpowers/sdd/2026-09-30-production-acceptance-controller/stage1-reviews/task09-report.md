# Task 9 review: guest CONNECT proxy (phase M4)

Reviewer: independent Stage 1 reviewer, 2026-11-17. Offline review only: injected fakes, no VM, network, browser or Swift run.

## 1. Verdict

**REJECT.** The destination path is sound: no DNS, exact two-host `:443` match, fixed CID 2 / port 4050, opaque enum-only control. But four problems are serious. The parser rejects the CONNECT request Chromium actually sends. Ordinary per-tunnel events end the whole run. The claimed vsock "transport authentication" is a self-comparison. And the tests for admission pinning and the serving-loop header limit still pass after the code they guard is deleted.

None of these findings opens a path to a destination other than the two release-bound hosts, and none can falsely report success. All of them fail closed.

## 7. Notes for the whole-M4 review

1. **Whole-run latching on per-tunnel events** (T9-2) applies to both proxy and broker. It needs one design decision for both, plus a Task 23 scenario with idle pooled connections across HOLD.
2. **Broker sequence ordering.** The broker requires the strictly next `sequence` per accepted control (`EgressBroker.swift:394`). Each of 16 physical relay slots is served by an independent task (`runRelays`). Two proxy tunnels opened close together can reach the broker out of order, which fails the run with `.replay`. The proxy assigns sequences at CONNECT-parse time and does not serialize vsock connects. This fails closed, but it should be resolved before Task 23.
3. **No host vsock listener or relay exists yet.** Whatever authenticates a guest stream (T9-3) has to live there. Today both sides compare the capability with themselves.
4. **Topology versus the verifier.** `topology.py:1986-1988` approves an established loopback connection to `:3128` only from UID 10002 (browser). Design §7 has the verifier (10003) making its fixed `/api/me` GET through the proxy. That connection would be reported as drift. Separately, the proxy does not check peer credentials, so any guest UID that has loopback can tunnel. Containment then rests on the route gate and the topology sampling.
5. **Nominal seals can be copied.** `dataclasses.replace()` on a sealed `NativeAdmissionPolicy` keeps `_seal` and skips `qualify_native_admission` validation; `topology_test.py:1565,1599,1698` do this. The amendment's statement that nominal handles are no sandbox against same-process code covers it. Do not count these seals as evidence of validation.
6. **The control's phase and event are not enforcement** (T9-7). The route gate remains the only phase authority for egress.
