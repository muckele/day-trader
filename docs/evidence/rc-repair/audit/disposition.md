## Reachability and remaining risk

The backend image runs Node (`backend/Dockerfile`) and server startup imports Express/Axios and enables `express.json()` (`backend/server.js`). Its fixed body-parser 2.3.0 is locked. Zero package advisories does not cover the EOL Node20 runtime, system libraries, deployment configuration or supply-chain compromise. The separate RUNTIME-001 change remains required.

The frontend Docker build uses Node and react-scripts, but the final image copies only static output into nginx. Babel/SVGO/PostCSS/Rollup/minifier/serialization chains are build tooling; Express/ws/node-forge are developer-server/test tooling. Their high findings remain material for hostile source/assets/configuration and exposed developer services. Installing with `--ignore-scripts` does not suppress later explicit build/test execution. See the existing per-high-package analysis in `../../phase3-security-report.md` and raw advisory IDs/installed paths in the fresh JSON; npm's proposed react-scripts 0.0.0 replacement is not a safe migration plan.

Browser dependency exposure is assessed separately. Recharts is imported in Portfolio, Home, Stock and other pages and can include lodash; lodash is locked at the previously patched 4.18.1. React Router 6.30.6 remains a browser dependency. `frontend/src/App.js` uses declarative BrowserRouter: the [maintainer SSR hydration advisory](https://github.com/remix-run/react-router/security/advisories/GHSA-337j-9hxr-rhxg) excludes declarative mode. The separate [navigation advisory](https://github.com/remix-run/react-router/security/advisories/GHSA-wrjc-x8rr-h8h6) requires attacker-supplied navigation paths; reviewed calls use fixed internal routes or fixed /stock/ and /research/ prefixes. No confirmed application exploit path for these remaining findings was established by the bounded review. Router maintenance and tooling debt remain open.

Node upgrades do not clear npm advisory findings. OS/nginx image advisories, actual image digests and production configuration require their separate available image/security checks. These audits establish neither release readiness nor deployed acceptance.
