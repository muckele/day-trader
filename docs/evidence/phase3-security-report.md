## Guarded external command

Implemented `backend/scripts/external-paper-acceptance.js`; native fetch with 10-second request timeout and redirects rejected, no .env auto-loading. Dry-run validates all order controls and returns before reading credentials or making requests. Network mode separately requires `--authorize-external-paper-test`, exact paper origin (no trailing slash/alias), expected dedicated account ID, symbol allowlist, integer quantity, explicit limit and maximum notional (integer cent arithmetic), and descriptive test prefix with cryptographically unique UUID client ID. It prints the test client ID before any network request for interrupted-run reconciliation.

Account identity/status/USD/cash, open clock, active tradable US equity, empty positions and no open orders are checked before one buy-limit POST. POST is never retried even on ambiguous failure. Lookup and cancellation identify the exact generated client ID, broker ID, symbol, side, quantity, order type and price. At most one single-order DELETE and three confirmation lookups follow; HTTP cancellation alone is never considered proof. Terminal status is required for confirmed cleanup. Existing resources are never canceled; no reset/cancel-all/position-close endpoint exists. Filled shares are reported and retained, requiring operator action. Dedicated-account emptiness is a snapshot; operator must reserve exclusive use of that account during acceptance.

Exit 0: dry-run or completed terminal zero-fill test; exit 2: residual filled shares or cancellation still nonterminal; exit 1: invalid controls, failed provider/readiness/ownership/transport checks. A lookup or cancel transport failure also fails closed and requires manual reconciliation of the printed client ID before any future run. This tool tests the provider boundary; it does not substitute for durable lifecycle or deployed-environment acceptance.

Safe dry-run command (executed locally with placeholder account ID and no credentials):

```sh
node backend/scripts/external-paper-acceptance.js --dry-run \
  --expected-account-id dedicated-paper-account \
  --paper-origin https://paper-api.alpaca.markets \
  --symbol-allowlist AAPL --symbol AAPL \
  --max-notional 10.00 --limit-price 1.00 --quantity 1 --test-prefix phase3
```

Later, only after separate explicit authorization and using a dedicated account with no positions/open orders, run the same command replacing `--dry-run` with `--authorize-external-paper-test` and replacing the placeholder expected ID with the verified dedicated paper account ID. Inject APCA_API_KEY_ID/APCA_API_SECRET_KEY through the operator's secure environment, never command arguments or this report. The intentionally low $1 limit bounds one share to $1; it is not designed to prove a fill. Do not increase price beyond a reviewed explicit maximum.

Controlled unit validation: `node --test backend/tests/externalPaperAcceptance.test.js` — **12 passed, 0 failed**, covering zero-network dry-run/refusals, uniqueness, readiness/account mismatch, one POST, timeout lookup without duplicate POST, foreign-resource refusal, bounded uncertain cancellation, residual filled shares/no liquidation, CLI rejection and transport-origin refusal.
