## 2. Authority and threat model

The host/kernel/hypervisor, guest kernel, immutable bootstrap, controller, proxy and broker remain trusted. Webpage, Chromium family, serialized observations and all caller-authored success claims are untrusted. Nominal Python/JS/Swift handles protect accidental or untrusted-data substitution within trusted embeddings; they are not a sandbox against malicious same-process code.

One `BootstrapComposition` owns the run from first acquisition through terminal cleanup. There are three separate authority contexts: Python bootstrap owns original Task8 children and physical pipes; controller JS owns controller-local `RolePort`, `RoleHandle`, transaction and grant WeakMap/WeakSet entries; original browser-worker JS owns a different module instance and worker-local reservation, effect grant and launched-browser cleanup owner. Swift independently validates guest evidence and owns the existing host lifecycle boundary. No nominal object crosses a process boundary. In particular, a controller `RoleHandle` is neither a worker grant nor the return type of a worker launch. Each trusted embedding creates its own nominal objects only after independently checking its original private-channel provenance.

The event-source addition is limited to guest bootstrap. No role UID, untrusted-role syscall allowance or inherited role FD inventory is relaxed. Browser/controller/verifier still cannot create AF_VSOCK; the proxy alone uses CID2/service4050. Existing protocol-scalar-zero socket policy, io_uring/alternate-ABI/FD-theft restrictions, sandbox and no-console boundaries remain unchanged.

Bootstrap's finite supervisor may retain its existing original-child wait/stop authority and the event descriptors defined in section 7. It accepts no arbitrary syscall, audit rule, executable, PID, FD, address, path or shell request. There is no general root service or post-start administrative endpoint. Child-authored identities never choose cleanup targets.

## 3. Fixed identities, types and interfaces

New wire documents use strict M1 decoding/canonicalization: ASCII, exact fields, duplicate/unknown-key rejection, integers distinguished from booleans, safe integers only, finite sizes. `RunId` and private `ChildId`/`PipeId` are 32 lowercase hex characters. `Digest` is 64 lowercase hex characters. `Epoch`, `Generation` and `Sequence` are positive safe integers. Wall and monotonic values in this amendment are integer milliseconds; a monotonic value crosses only processes in the same guest boot, never host/guest clock domains.

`CompositionBinding` has exactly `{version:1, runId, manifestDigest, configIdentity, rolePolicyDigest, epoch, expiresAtMs}`. Epoch is allocated once by the original bootstrap; no resampling, reconnect or retry renews it. Generation begins at 1 and is invalidated permanently by failure/cancellation/drift. Every owner additionally retains its original process/endpoint identity privately. Sequence is strictly increasing per direction on each channel; replay/gap/overflow is terminal. Digests and IDs correlate independently verified facts; they do not authenticate themselves.

Finite role IDs remain `CONTROLLER`, `BROWSER`, `VERIFIER`, `PROXY`, UIDs 10001–10004. Role FDs remain 0/1/2 null, 3 command, 4 result. Python retains physical child endpoints. JS's `privatePipe` is a nominal finite subchannel on the original controller/bootstrap channel, bound to exactly one original child/pipe pair; bootstrap forwards only that role's fixed frames. It never transfers new FDs. Existing `WAITING\n` readiness precedes bootstrap input.

Controller private frame actions are exactly `ADOPT`, `PREPARE_BROWSER`, `COMMIT_BROWSER`, `CANCEL`, `WAIT_EXIT`, `STOP_OWNED`, `PROXY_CURRENT`, `TOPOLOGY_CURRENT`, `RESULT`. A frame has exactly `{version:1, binding, sequence, role, childId, pipeId, action, payload, mac}`. ADOPT/`BootstrapRoleBinding.adopt` accepts only the existing BROWSER/VERIFIER port kinds; browser preparation/commit/cancel target BROWSER, PROXY_CURRENT targets PROXY and TOPOLOGY_CURRENT targets CONTROLLER. WAIT_EXIT/STOP_OWNED may target only the four original owners. Action-specific payloads are fixed schemas; maximum body 16384 bytes, depth 8, with a four-byte big-endian length. Bootstrap allocates distinct 32-byte keys for the physical CONTROLLER, BROWSER and PROXY channels; no role receives another role's key. MAC input is `acceptance:bootstrap-composition:v1\0` followed by ASCII `<channel-role>:<direction>\0` and the canonical frame without `mac`; direction is exactly `TO_BOOTSTRAP` or `FROM_BOOTSTRAP`. Each physical direction starts at sequence1, increments by one, and never resets. The role/child/pipe in a controller subchannel frame must match the immutable original role map. No key in argv/environment/file/public output; no new signing authority. Section6 specifies the proxy's separate two-byte framing and versioned migration.

The initial bootstrap-only record on the independently audited controller FD3 is exactly `{version:1,kind:BOOTSTRAP_INIT,binding,channelKeyHex,roles}`; `roles` is the fixed ordered four-entry array of `{role,childId,pipeId}` assigned by the original owner, and `channelKeyHex` is64 lowercase hex. It has the same length/depth bound, precedes all action frames, is consumed once and is never logged. Initial delivery is authenticated by the inherited pipe's independently established provenance, not by a key delivered by an arbitrary pipe. Request payloads are exactly: ADOPT `{}`; PREPARE_BROWSER `{proofDigest,generation,expiresAtMs,monotonicDeadlineMs}`; COMMIT_BROWSER `{grantId,generation}`; CANCEL `{generation,cleanupEndsAtMonotonicMs}`; WAIT_EXIT/STOP_OWNED `{remainingMs,cleanupEndsAtMonotonicMs}`; PROXY_CURRENT/TOPOLOGY_CURRENT `{generation}`. `grantId` is32 lowercase hex. RESULT has exactly `{requestSequence,result}` and is selected by the original request. ADOPT result is `{kind,runId,uid,childId,pipeId,waiting,confined,attestationDigest}`; PREPARE_BROWSER result is `{grantId,proofDigest,generation,expiresAtMs,monotonicDeadlineMs}`; COMMIT_BROWSER/CANCEL result is `{status:ACTIVE|CANCELLED,generation}` with the one matching status; WAIT_EXIT/STOP_OWNED returns `OwnedStopReceipt`; PROXY_CURRENT returns `ProxyRuntimeObservation`; TOPOLOGY_CURRENT returns `{proofDigest,eventCheckpoint}`. An unsolicited/mismatched RESULT cannot establish authority. Role/child/pipe is checked against the immutable initial map, never used for lookup of arbitrary resources. Nominal controller child/pipe objects are recovered from that trusted map, never from serialized values.

The independently audited original BROWSER FD3 receives exactly one `{version:1,kind:BROWSER_WORKER_INIT,binding,role:BROWSER,childId,pipeId,channelKeyHex}` before worker commands, using the same four-byte framing/bounds. It must agree with the worker's independently supplied immutable expected binding and audited current process/FD3/FD4 identities. Task8 bootstrap retains the matching physical endpoints and original child owner; no reconnect, inherited lookalike pipe or controller-supplied key is accepted. ## 4. Bootstrap order and invariants

The only successful state order is `NEW → PROBING → PROBES_EXITED → ROLES_WAITING → PROXY_READY → WATCHING → ADMITTED → BROWSER_COMMITTED`. Any error transitions to terminal `FAILED`; cleanup state is independently `PENDING|PROVEN|UNCERTAIN`. There is no restart/resume transition. `BROWSER_COMMITTED` is a future Task13 effect boundary, exercised with an inert launch recorder in this offline slice.

1. Register the composition's acquisition/cleanup obligation with Task10 before opening an observation handle, entering a callback, starting a probe or creating a child. Check immutable input, host device/run authority and deadline.
2. In `PROBING`, run all fixed probes before persistent `start_roles`. Each fresh probe family uses the accepted fixed per-role `/.root` and `/.state` scopes. Retain ownership before setup. Require actual attempted markers, bounded result and independently owned receiver facts, original-family exit/reap and empty-scope removal before the next case. Any uncertainty blocks persistent roles. Do not recursively delete unknown content or reuse occupied roots.
3. Seal `CompletedProbeEpoch` with the exact binding, ordered catalogue/result digest, fixture inventory digest, and all family-exit/scope-cleanup proofs. It has no public constructor from a list of passing booleans. Different run, manifest, role policy, epoch, fixture inventory or expired binding invalidates it.
4. Start and audit four persistent waiting roles once. Bind nominal JS handoffs to their original ownership. The proxy may receive its fixed admission configuration and become ready; browser/verifier remain waiting.
5. Install the one event source, retain its owner before setup, verify source readiness and loss counters, then take the first admissible snapshot. Event installation must precede that snapshot. Events caused by already-completed probe/role setup do not establish admission. Installation/readiness failure is terminal.
6. Obtain event checkpoints bracketing the complete initial inventory. Drain complete event records and verify unchanged generation/loss state, original roles, exact proxy runtime owner, host devices, appliance and deadlines before publishing proof. A change even if reverted between snapshots fails. An unproved drain/barrier is unavailable, never an empty-event success.
7. Current admission resamples topology/roles/proxy/source health under the same epoch and supervision, using retained `CompletedProbeEpoch`. It must not rerun fresh probes or respawn roles. Recheck effect authority again as section 5 requires.

The existing twelve Task10 IDs remain exactly: `BROWSER_FD_DONOR`, `BROWSER_HELPER_IPV4`, `BROWSER_HELPER_IPV6`, `BROWSER_IO_URING`, `BROWSER_IPV4_TCP`, `BROWSER_IPV6_TCP`, `BROWSER_UDP`, `BROWSER_VSOCK`, `CONTROLLER_DNS_TCP`, `CONTROLLER_DNS_UDP`, `PROXY_VSOCK_CONTROL`, `VERIFIER_IPV4_TCP`. Require all underlying Task8 cases, including UID/capability/view/FD/TSYNC/ABI checks; the twelve rows are a finite projection, not permission to omit original cases.

Topology remains no NIC/default route/DNS relay, exactly guest TCP `127.0.0.1:3128` proxy, no `::1` listener or unexpected UNIX service, exact host devices and four roles. Ordinary accepted proxy streams are not extra listeners. No proof can upgrade a missing/failed/skipped probe or receiver to success.

At admission BROWSER and VERIFIER remain waiting; CONTROLLER and PROXY service their fixed channels. The accepted all-four-waiting snapshot predicate is amended to these exact lifecycle states. After the one committed browser launch, its original family becomes active; identities, policy, descriptors and ownership remain bound. Current checks permit only that internally reserved lifecycle transition, not arbitrary changed role facts. Normal observed descendant exit is correlated to the same family; unexpected persistent-role death is terminal.

## 5. Original-child activation and one cleanup deadline

Preserve `RolePort.activateOnce(grant)` and `RoleHandle={privatePipe,waitExit(deadline),stopOwned(deadline)}`. Their `deadline` argument is a remaining duration in milliseconds, clamped to the same original cleanup budget. Change the legacy hardcoded `stopOwned(120000)` compensation to the actual remaining shared budget; this accepted Task8 change requires independent review.

A controller browser grant is a controller-local private nominal object with exact original child/pipe, binding, admission proof digest, generation, one-use nonce, wall expiry and guest monotonic deadline. Purpose remains `CONFINEMENT_PROVED`, session is null. Worker PREPARE makes a separately sealed `WorkerLaunchReservation` and a worker-only one-use effect grant with the same verified facts plus reservation/commit correlation. Neither is constructed from a controller object. Verifier purpose remains `PRIOR_SESSION`; no verifier/session behavior is implemented here. Copies, serialized reconstructions, foreign roles/pipes/epochs, extra fields, replays and absent current proof fail closed.

Consume each context's one-use authority synchronously before callbacks/await. Retain transaction/reservation ownership, mark preparation in flight, and validate current reservation under one local lock transition. After every fallible or awaited operation, recheck identity, monotonic/wall deadlines, terminal/cancellation/generation and original event-source checkpoint. On COMMIT the worker requests REFRESH; bootstrap must obtain a new current proof and event barrier under the same epoch, not reuse PREPARED or an old snapshot. The correlated CURRENT response cannot extend either deadline. Immediately before the captured launch call, the worker drains/processes pending original-channel terminal/cancel records, validates the current event fence, reads its own fresh wall/monotonic clocks, checks local generation/terminal/reservation state and consumes its worker-only effect latch in one synchronous guard with no intervening await/user callback/alternate launch API. Failure or unavailable delivery/ordering fence means zero launches. A queued, expired, cancelled or copied reservation must record zero launches. Successful local return retains the actual browser owner; later failure is terminal and compensated through that original owner plus the original Task8 family.

Cancellation is sent only on the original private channels and invalidates both local contexts permanently; EOF, malformed framing, missed sequence, source loss and child death have the same effect. Preparation/worker acknowledgement alone is not permission. Tests load separate controller and worker module contexts with disjoint nominal stores, pass only real Python-forwarded bytes between them, and inject expiry/cancel/event failure before PREPARED, between COMMIT and REFRESH, after CURRENT and at the final synchronous guard. The future worker must use this worker-local guard; a controller callback or host post-return check alone does not close R6. Cross-process event-drain/commit ordering must be demonstrated, not assumed from an empty local queue: if no finite native fence can be derived, return `NATIVE_EFFECT_FENCE_UNAVAILABLE` and retain operational denial. Inert fence tests prove contract behavior only.

At first terminal cleanup, allocate one absolute guest monotonic end at `start+60000ms`, additionally capped by an independent real monotonic end. Authenticated cancel/stop frames propagate that same `cleanupEndsAtMonotonicMs`; receivers clamp to the earliest end already seen and never renew it. A worker/proxy terminal includes its original `failedAtMonotonicMs`, so bootstrap uses the earliest terminal time, not receipt time. If EOF/bare STOP prevents authenticated budget delivery, revoke immediately, perform nonblocking cleanup only and retain unresolved owners; it does not authorize a new timeout. Host receives remaining duration and uses its own monotonic cap, never compares guest monotonic timestamps to host time. Every capture, probe, role, JS compensation, proxy, event, host lifecycle and late-settlement cleanup uses that end. No fresh per-child or per-language 60/120-second window. Each loop checks remaining time; callback waits are bounded. A timed-out callback may still be running; report uncertainty, keep its original owner, and never overlap another stop on that owner. No callback is claimed forcibly terminated.

Pending obligations are visible to the gate before external calls. N5-A requires a registered capture owner even when no snapshot exists. N5-B requires an ordinary observation-close exception to produce `CleanupFailure(originalOwner)` and retain any prior typed chain. Concurrent admit/drift/status calls must report pending/uncertain cleanup, including before capture returns. Cleanup may become PROVEN only when acquisition has settled and every original obligation has a valid terminal receipt. Late acquisition invalidates earlier retirement. Close retries use the nominal owner, never a recycled raw FD or PID.

## 6. Descendant probes, independent receivers and proxy provenance

### 6.1 Finite inherited proxy protocol

FD3 initialization is a two-byte big-endian body length, maximum4096 bytes, strict ASCII/depth8. Legacy `{version:1,kind:PROXY_BOOTSTRAP,...}` remains exactly Task9's decoder schema and cannot qualify composition. The new exact initializer is `{version:2,kind:PROXY_COMPOSITION_INIT,binding,childId,pipeId,channelKeyHex,proxyBootstrap}`; nested proxyBootstrap is that unchanged full v1 bootstrap object. Compare binding.runId/configIdentity/manifestDigest/rolePolicyDigest/expiresAtMs exactly to nested runId/configIdentity/manifestIdentity/rolePolicyIdentity/expiresAt respectively; both expiry fields already use milliseconds. The original Task9 policy still checks capability, origins, firstSequence, runtimeIdentity and limits independently. Epoch comes only from original composition policy. Bounds apply to the complete nested document. Unsupported version/mismatch/second initializer is terminal before owner minting.

After v2 init FD3 accepts only framed v2 commands or the legacy raw four bytes `STOP`; EOF always revokes. Framed bodies are at most4096 bytes/depth8 with a two-byte length. A first pair `ST` selects only the following `OP`; it cannot be a valid bounded length. No other unframed bytes are accepted. V2 command is exactly `{version:2,kind,binding,childId,pipeId,sequence,payload,mac}` with kind `PROXY_CURRENT` and payload `{requestId,generation}`, or kind `PROXY_STOP` and payload `{requestId,cleanupEndsAtMonotonicMs}`. requestId is32-hex and unique; at most one current request is outstanding. The actual serving loop parses and handles these commands through the retained `NativeSockets` command/stop selector, not a disconnected callback decoder.

FD4 v2 frames use a two-byte body length, maximum16384 bytes/depth8, with exact outer `{version:2,kind,binding,childId,pipeId,sequence,payload,mac}`. Kind/payload is exactly `PROXY_READY`/`{observation}`, `PROXY_CURRENT`/`{requestId,requestSequence,observation}`, or `PROXY_TERMINAL`/`{requestId,requestSequence,runtimeId,code,usedBytes,cleanupStatus,failedAtMonotonicMs}`. Terminal request fields are the matching stop request, or `requestId:""`/requestSequence0 for an autonomous terminal; this zero sentinel is not a channel Sequence. runtimeId is empty only if no owner was minted. code is exactly the accepted `_OUTCOME_CODES`: `BYTE_LIMIT|CAPACITY|CHANNEL_DENIED|CLOCK|COMPLETE|CONFIG_DENIED|CLEANUP_UNCERTAIN|EXPIRED|IDENTITY_MISMATCH|IDLE_TIMEOUT|INTERNAL_FAILURE|LISTENER_DENIED|TERMINAL|TRANSPORT_LOST`; usedBytes is0..1073741824, cleanupStatus is `PROVEN|UNCERTAIN`, and failedAtMonotonicMs is the first terminal instant even for normal COMPLETE. The terminal is emitted at most once and cannot mint/revive authority. A pre-initialization failure has no trusted v2 channel and only closes/reports its existing finite failure; it cannot assert a v2 binding.

These frames use the PROXY role/directional MAC and contiguous sequences defined in section3; the initializer has no sequence, then each direction starts at1. Bootstrap correlates original child/pipe/runtime, full binding, requestId/requestSequence and observation sequence. READY is only initial readiness. CURRENT must be freshly produced inside the live loop after that request, with observedAtMonotonicMs between send and receive in the same guest clock domain; request-to-receipt at most100ms, unexpired binding and unchanged generation. Failure, timeout, unsolicited current, truncation, oversized/duplicate field, gap/replay or pipe death revokes the owner and keeps original cleanup obligations. Legacy FD4 remains exactly the maximum512-byte, two-byte-prefixed v1 `PROXY_RESULT` terminal for v1 initialization; v2 uses its v2 terminal and never interprets a legacy result as current evidence. No FD or raw endpoint is transferred.

Authenticated PROXY_STOP carries the existing shared absolute guest cleanup end; bare STOP/EOF uses section5's immediate revocation/nonblocking-only fallback, never a new cleanup window. Tests must traverse `admitted_inherited_main`→actual `_inherited_entry` decoder→config admission→`NativeSockets` command parser→real `serve_proxy`→FD4 writer with inert byte streams/OS/clock.
