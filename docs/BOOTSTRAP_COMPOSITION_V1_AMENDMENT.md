## 2. Authority and threat model

The host/kernel/hypervisor, guest kernel, immutable bootstrap, controller, proxy and broker remain trusted. Webpage, Chromium family, serialized observations and all caller-authored success claims are untrusted. Nominal Python/JS/Swift handles protect accidental or untrusted-data substitution within trusted embeddings; they are not a sandbox against malicious same-process code.

One `BootstrapComposition` owns the run from first acquisition through terminal cleanup. Python bootstrap retains original Task8 child owners and pipe endpoints. Controller-side JS receives authenticated finite views of those exact owners through its existing inherited bootstrap pipe. Swift independently validates guest evidence and owns the existing host lifecycle boundary. No Python object becomes a JS nominal object by serialization. Only the trusted JS embedding can mint/adopt its local handoff and grant objects after checking the original private-channel binding.

The event-source addition is limited to guest bootstrap. No role UID, untrusted-role syscall allowance or inherited role FD inventory is relaxed. Browser/controller/verifier still cannot create AF_VSOCK; the proxy alone uses CID2/service4050. Existing protocol-scalar-zero socket policy, io_uring/alternate-ABI/FD-theft restrictions, sandbox and no-console boundaries remain unchanged.

Bootstrap's finite supervisor may retain its existing original-child wait/stop authority and the event descriptors defined in section 7. It accepts no arbitrary syscall, audit rule, executable, PID, FD, address, path or shell request. There is no general root service or post-start administrative endpoint. Child-authored identities never choose cleanup targets.

## 3. Fixed identities, types and interfaces

New wire documents use strict M1 decoding/canonicalization: ASCII, exact fields, duplicate/unknown-key rejection, integers distinguished from booleans, safe integers only, finite sizes. `RunId` and private `ChildId`/`PipeId` are 32 lowercase hex characters. `Digest` is 64 lowercase hex characters. `Epoch`, `Generation` and `Sequence` are positive safe integers. Wall and monotonic values in this amendment are integer milliseconds; a monotonic value crosses only processes in the same guest boot, never host/guest clock domains.

`CompositionBinding` has exactly `{version:1, runId, manifestDigest, configIdentity, rolePolicyDigest, epoch, expiresAtMs}`. Epoch is allocated once by the original bootstrap; no resampling, reconnect or retry renews it. Generation begins at 1 and is invalidated permanently by failure/cancellation/drift. Every owner additionally retains its original process/endpoint identity privately. Sequence is strictly increasing per direction on each channel; replay/gap/overflow is terminal. Digests and IDs correlate independently verified facts; they do not authenticate themselves.

Finite role IDs remain `CONTROLLER`, `BROWSER`, `VERIFIER`, `PROXY`, UIDs 10001–10004. Role FDs remain 0/1/2 null, 3 command, 4 result. Python retains physical child endpoints. JS's `privatePipe` is a nominal finite subchannel on the original controller/bootstrap channel, bound to exactly one original child/pipe pair; bootstrap forwards only that role's fixed frames. It never transfers new FDs. Existing `WAITING\n` readiness precedes bootstrap input.

New private frame actions are exactly `ADOPT`, `PREPARE_BROWSER`, `COMMIT_BROWSER`, `CANCEL`, `WAIT_EXIT`, `STOP_OWNED`, `PROXY_CURRENT`, `TOPOLOGY_CURRENT`, `RESULT`. A frame has exactly `{version:1, binding, sequence, role, childId, pipeId, action, payload, mac}`. Action-specific payloads are fixed schemas; maximum total frame 16384 bytes, depth 8, with a four-byte big-endian length. Use HMAC-SHA256 with domain `acceptance:bootstrap-composition:v1\0`; channel key is 32 private bytes established over the audited inherited channel before untrusted execution. No key in argv/environment/file/public output; no new signing authority. Existing Task9 bootstrap/result framing is retained inside its exact proxy channel rather than silently reinterpreted as this frame.

The initial bootstrap-only record on the independently audited controller FD3 is exactly `{version:1,kind:BOOTSTRAP_INIT,binding,channelKeyHex,roles}`; `roles` is the fixed ordered four-entry array of `{role,childId,pipeId}` assigned by the original owner, and `channelKeyHex` is64 lowercase hex. It has the same length/depth bound, precedes all action frames, is consumed once and is never logged. This private pipe's independently established provenance authenticates that initial delivery; self-authenticated bytes from an arbitrary pipe are rejected. Subsequent MACs cover the canonical frame without its `mac` field. Request payloads are exactly: ADOPT `{}`; PREPARE_BROWSER `{proofDigest,generation,expiresAtMs,monotonicDeadlineMs}`; COMMIT_BROWSER `{grantId,generation}`; CANCEL `{generation}`; WAIT_EXIT/STOP_OWNED `{remainingMs}`; PROXY_CURRENT/TOPOLOGY_CURRENT `{generation}`. `grantId` is32 lowercase hex. RESULT has exactly `{requestSequence,result}` and is selected by the original request. ADOPT result is `{kind,runId,uid,childId,pipeId,waiting,confined,attestationDigest}`; PREPARE_BROWSER result is `{grantId,proofDigest,generation,expiresAtMs,monotonicDeadlineMs}`; COMMIT_BROWSER/CANCEL result is `{status:ACTIVE|CANCELLED,generation}` with the one matching status; WAIT_EXIT/STOP_OWNED returns `OwnedStopReceipt`; PROXY_CURRENT returns `ProxyRuntimeObservation`; TOPOLOGY_CURRENT returns `{proofDigest,eventCheckpoint}`. An unsolicited/mismatched RESULT cannot establish authority. Role/child/pipe is checked against the immutable initial map, never used for lookup of arbitrary process resources. Nominal JS child/pipe objects are recovered from that trusted map, never from serialized values.

## 4. Bootstrap order and invariants

The only successful state order is `NEW → PROBING → PROBES_EXITED → ROLES_WAITING → PROXY_READY → WATCHING → ADMITTED → BROWSER_COMMITTED`. Any error transitions to terminal `FAILED`; cleanup state is independently `PENDING|PROVEN|UNCERTAIN`. There is no restart/resume transition. `BROWSER_COMMITTED` is a future Task13 effect boundary, exercised with an inert launch recorder in this offline slice.

1. Register the composition's acquisition/cleanup obligation with Task10 before opening an observation handle, entering a callback, starting a probe or creating a child. Check immutable input, host device/run authority and deadline.
2. In `PROBING`, run all fixed probes before persistent `start_roles`. Each fresh probe family uses the accepted fixed per-role `/.root` and `/.state` scopes. Retain ownership before setup. Require actual attempted markers, bounded result and independently owned receiver facts, original-family exit/reap and empty-scope removal before the next case. Any uncertainty blocks persistent roles. Do not recursively delete unknown content or reuse occupied roots.
3. Seal `CompletedProbeEpoch` with the exact binding, ordered catalogue/result digest, fixture inventory digest, and all family-exit/scope-cleanup proofs. It has no public constructor from a list of passing booleans. Different run, manifest, role policy, epoch, fixture inventory or expired binding invalidates it.
4. Start and audit four persistent waiting roles once. Bind nominal JS handoffs to their original ownership. The proxy may receive its fixed admission configuration and become ready; browser/verifier remain waiting.
5. Install the one event source, retain its owner before setup, verify source readiness and loss counters, then take the first admissible snapshot. Event installation must precede that snapshot. Events caused by already-completed probe/role setup do not establish admission. Installation/readiness failure is terminal.
6. Obtain event checkpoints bracketing the complete initial inventory. Drain complete event records and verify unchanged generation/loss state, original roles, exact proxy runtime owner, host devices, appliance and deadlines before publishing proof. A change even if reverted between snapshots fails. An unproved drain/barrier is unavailable, never an empty-event success.
7. Current admission resamples topology/roles/proxy/source health under the same epoch and supervision, using retained `CompletedProbeEpoch`. It must not rerun fresh probes or respawn roles. Recheck effect authority again as section 5 requires.

The existing twelve Task10 IDs remain exactly: `BROWSER_FD_DONOR`, `BROWSER_HELPER_IPV4`, `BROWSER_HELPER_IPV6`, `BROWSER_IO_URING`, `BROWSER_IPV4_TCP`, `BROWSER_IPV6_TCP`, `BROWSER_UDP`, `BROWSER_VSOCK`, `CONTROLLER_DNS_TCP`, `CONTROLLER_DNS_UDP`, `PROXY_VSOCK_CONTROL`, `VERIFIER_IPV4_TCP`. Require all underlying Task8 cases, including UID/capability/view/FD/TSYNC/ABI checks; the twelve rows are a finite projection, not permission to omit original cases.

Topology remains no NIC/default route/DNS relay, exactly guest TCP `127.0.0.1:3128` proxy, no `::1` listener or unexpected UNIX service, exact host devices and four roles. Ordinary accepted proxy streams are not extra listeners. No proof can upgrade a missing/failed/skipped probe or receiver to success.

At admission BROWSER and VERIFIER remain waiting; CONTROLLER and PROXY service their fixed channels. The accepted all-four-waiting snapshot predicate is amended to these exact lifecycle states. After the one committed browser launch, its original family becomes active; identities, policy, descriptors and ownership remain bound. Current checks permit only that internally reserved lifecycle transition, not arbitrary changed role facts. Normal observed descendant exit is correlated to the same family; unexpected persistent-role death is terminal.

Guest-to-host composition evidence extends the legacy topology envelope explicitly: `{version:2,payload,mac}`, where `payload` is the existing exact topology payload plus `composition:{binding,probeEpochDigest,fixtureInventoryDigest,eventCheckpoint,proxyRuntimeId}`. `EventCheckpoint` is exactly `{binding,generation,sequence,sourceIdentity,lostCount}`; `sourceIdentity` is the private32-hex identity of the original event owner, and `lostCount` must equal its verified installation baseline. MAC covers the canonical payload with domain `acceptance:bootstrap-composition:v1\0`. The current topology envelope bound131072bytes/depth12 is retained, distinct from the smaller action frames. Legacy envelope version1 is inspection/test-only for this composition. Host and guest strictly check every nested primitive and correlate all new values with original nominal authority; valid-MAC self-consistent claims alone cannot qualify.

Purpose remains `CONFINEMENT_PROVED`, session is null. Verifier purpose remains `PRIOR_SESSION`; no verifier/session behavior is implemented here. Copies, serialized reconstructions, foreign roles/pipes/epochs, extra fields, replays and absent current proof fail closed.

Consume once synchronously before callbacks/await. Retain transaction ownership, mark preparation in flight, and validate current reservation under one lock transition before preparation. After every fallible or awaited operation, recheck identity, monotonic/wall deadlines, terminal/cancellation/generation and original event-source checkpoint. Immediately before the fixed worker launch call, consume the final effect latch and synchronously check those facts again; there is no intervening await, user callback or alternate launch API. An expired or cancelled grant must record zero launches. Late success is terminal and compensated through original ownership.

Cancellation is sent only on the original private channel and invalidates the worker transaction permanently; EOF, malformed framing, missed sequence, source loss and child death have the same effect. Preparation/worker acknowledgement alone is not permission. The future worker and controller must use the same guarded effect path; a host post-return expiry check alone does not close R6. Cross-process event-drain/commit ordering must be demonstrated by the authored protocol and inert adversarial interleavings; if native ordering cannot be established, operational admission stays unavailable.

At first terminal cleanup, allocate one absolute monotonic end at `start+60000ms`, additionally capped by an independent real monotonic end. Every capture, probe, role, JS compensation, proxy, event, host lifecycle and late-settlement cleanup uses that end. No fresh per-child or per-language 60/120-second window. Each loop checks remaining time; callback waits are bounded. A timed-out callback may still be running; report uncertainty, keep its original owner, and never overlap another stop on that owner. No callback is claimed forcibly terminated.

Pending obligations are visible to the gate before external calls. N5-A requires a registered capture owner even when no snapshot exists. N5-B requires an ordinary observation-close exception to produce `CleanupFailure(originalOwner)` and retain any prior typed chain. Concurrent admit/drift/status calls must report pending/uncertain cleanup, including before capture returns. Cleanup may become PROVEN only when acquisition has settled and every original obligation has a valid terminal receipt. Late acquisition invalidates earlier retirement. Close retries use the nominal owner, never a recycled raw FD or PID.

## 7. One finite native event source

Selected mechanism: one bootstrap-owned `LinuxBootstrapEventSource` aggregates exactly Linux 6.8 audit unicast (`NETLINK_AUDIT`), route multicast (`NETLINK_ROUTE` link/address/IPv4+IPv6 route groups), kernel device uevents (`NETLINK_KOBJECT_UEVENT`), and inotify watches on `/etc` plus `/etc/resolv.conf`. Original child-control/result pipe death is observed by this same owner. No generic subscription API or user-selected rules exist.

Its finite event IDs are `DEVICE`, `NIC`, `ROUTE`, `DNS`, `LISTENER`, `UNIX`, `ROLE`, `OVERFLOW`, `SOURCE_DIED`. It holds exactly four native event descriptors plus its one wakeup pipe pair, and references existing owned role pipes without duplication/donation. A fixed selector owner closes those originals. Descriptors are CLOEXEC, nonblocking and bootstrap-only; none appears in role FDs0–4. The bootstrap-owned namespace views see every role relevant to admission.

Required guest kernel features, in addition to the existing eleven, are `CONFIG_AUDIT=y`, `CONFIG_AUDITSYSCALL=y`, `CONFIG_INOTIFY_USER=y`. Audit is enabled at guest boot (`audit=1`). During guest initialization bootstrap alone registers the exclusive audit receiver and fixed rules with `CAP_AUDIT_CONTROL`; it retains only the minimum audit control authority needed for fixed status checks/termination. It cannot process caller-selected administration. The four roles still drop every initial-namespace capability. Existing receiver/rules, unavailable capability/feature, rule mismatch or inability to retain isolation blocks admission. No audit daemon/package or host audit change is introduced.

Fixed audit rules select native AArch64 syscall-exit records for `bind`, `listen`, `clone`, `clone3`, `execve`, `execveat`, `exit`, `exit_group`, `setns`, `unshare`, `mount`, `umount2`, `pivot_root`, `chroot`, and `mknodat`. Native AArch64 does not supply separate fork/vfork syscall entries; do not invent them. Bind/listen capture IP/UNIX listener attempts even if the socket vanishes before a snapshot; netlink catches link/address/route/device changes; resolver watches catch writes/replacement/watch invalidation. Audit process identity is correlated with original bootstrap ownership, including descendants. Bootstrap heartbeat uses fixed `AUDIT_GET` requests and verifies configured receiver PID, enabled state, exact rules and unchanged lost counter. Relevant successful changes latch failure; unrecognized/malformed records, unsupported attribution or incomplete audit events also fail. Denied syscalls do not prove delivery and cannot authorize anything.

The only accepted role transition after admission is the one internally reserved browser-worker/Chromium launch and its descendants, identified by original family and pinned executable policy; this is not an arbitrary PID exception. All unexpected role exec/death or namespace/device mutation fails. No post-admission new listener or named/abstract UNIX service is allowed. If the eventual pinned browser needs additional services, qualification stops for a new finite policy decision. Anonymous intra-family IPC already allowed by Task8 is not a newly permitted service.

Limits: native message at most65536 bytes; userspace queue at most256 events and1MiB total; at most64 incomplete audit event groups; each incomplete group at most1000ms; source-health check interval at most100ms; audit backlog limit256 and rate limit0 (no intentional rate suppression). Any ENOBUFS/truncation, audit lost-counter increment, inotify overflow, uevent sequence discontinuity, unexpected sequence/reset, capacity breach, read/parse error, watch loss or source death latches terminal failure and increments generation. Do not silently retry, discard records or substitute polling. Multi-record audit groups must reach their fixed end marker; a status reply alone does not establish that all pending events were consumed.

Raw audit/netlink/inotify records, process/endpoint identities and paths stay in bounded private memory; no audit log file, raw console stream or exported diagnostic record is created. Only finite event/failure IDs and approved aggregate counts reach existing sanitized status. Bootstrap setup acknowledgements are accepted only while installing the exact fixed rules; they do not permit ignoring later unknown records.

Install all channels and fixed rules before the first accepted snapshot. `barrier()` brackets snapshot/activation with complete record processing and source-status checks. Unknown/lost pending history is failure. Continuous observation is required after admission; snapshots corroborate it. This is source-level architecture subject to native qualification, not a claim that asynchronous Linux telemetry makes an unobserved race impossible. Failure to prove the native ordering/coverage is an operational blocker.

Offline reference derivation must cover UAPI constants, message/attribute layouts, alignment, group masks, audit records/status/rules, inotify events, required syscalls and capabilities from the retained archive and pinned ABI sources. Record member path, byte hash and declaration lines independently; retain original bundle unchanged. New declarations may not be guessed from macOS or added to the untrusted-role filter. The coordinator's ruling authorizes only these minimum guest-bootstrap policy/reference additions; new dependencies/downloads, broader privileges, generic audit consumption or persistent administrative channels are stop conditions.
